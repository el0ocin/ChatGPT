# Temporary Credential Security SOP

This is the highest-risk part of the service.

Follow it exactly.

## Default rule
- Credentials are used only for active posting.
- Credentials are never stored in Notion.
- Credentials are never written into client notes, databases, or reusable docs.

## Approved flow
1. Client sends temporary credentials only when the job is ready to post.
2. Client stays available for any 2FA or verification prompts.
3. You log in, publish the listings, copy the live URLs, and log out.
4. You confirm the posting is complete.
5. Client immediately changes the password after delivery.

## Storage rule
- Do not paste passwords into Notion.
- Do not save them in checklists, docs, or browser password prompts.
- Do not leave the accounts logged in longer than needed.

## Preferred fallback
If a client does not want to share temporary credentials:
- switch to live co-posting
- share the copy and image order
- guide them through the actual posting session

## Client-facing language
`For account safety, I only use temporary credentials during the active posting session, I do not store them in Notion or anywhere permanent, and I ask every client to change the password right after delivery.`

## Red flags
- client wants you to keep long-term access
- client sends primary passwords they use everywhere
- client is unclear about ownership of the account
- client expects you to manage buyer chats indefinitely without agreement

If any of those happen, pause and reset the scope.
